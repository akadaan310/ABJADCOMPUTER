# ٠٨ — توليد الجذور خارج المعجم
# 08 — Non-dictionary root synthesis

> Generated by the ABJADCOMPUTER engine. Every value below is a sum of
> table look-ups and can be re-checked with pencil and paper.


## 1. What this does

A string with no lexical entry is still fully determined structurally. Its letters have weights; the weights give an address; the address has neighbours inside the corpus; and the poem itself states where each of its letters is articulated. A reading can be assembled from those four facts alone.

**What it is not.** This is a formal placement of a token inside this corpus. It is not a claim about attested Arabic lexicography, and a definition produced here is not evidence that a word exists or means anything in the language. The procedure is deterministic, which makes it checkable — not authoritative.

## 2. The two projections

Every token is read twice, at two expansion depths:

| projection | depth | what it reads |
|---|---|---|
| إنسيّ / manifest | 0 | the surface rasm as written — letters at face weight |
| جنّيّ / hidden | 1 | each letter replaced by its spelled name, then summed |

These are not two systems but one computation at two depths. The manifest reading is what the eye counts; the hidden reading is what the name of each sign counts.

## 3. Procedure

```
1. normalise      strip diacritics; fold hamza carriers onto ا; resolve ة by state
2. deconstruct    letter -> integer, by table look-up
3. root           drop ال, prefer strong consonants, re-admit weak ones if short
4. project        J at depth 0 (manifest) and depth 1 (hidden)
5. address        J -> digital root, ring position, container handle
6. cluster        corpus words nearest by |Δ|; dominant chapter of the container
7. render         compose the reading from steps 3–6
```

## 5. Determinism check

Re-running the procedure on the same token yields the same address, the same neighbours and the same text, because every step is a table look-up or a sum. Two tokens with the same letters in any order share a manifest address — the manifest projection is order-blind, the root extraction is not:

| token | manifest | root | hidden |
|---|---|---|---|
| زحقل | 145 | زحق | 280 |
| قلزح | 145 | قلز | 280 |
| حلزق | 145 | حلز | 280 |

Same manifest value, different roots — which is precisely the information the tree carries that the scalar address does not.
