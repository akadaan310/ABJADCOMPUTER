One node set carries two independent link systems.

```
TREE  (local, explicit)          GRAPH (global, containerised)
  corpus                           C<dr>.<ring>
    └── section  ×17                 ├── node  (any kind, any depth)
          └── line  ×109             ├── node
                └── hemistich ×218   └── node
                      └── word ×1005      ⇢ every pair one hop apart
                            └── expansion (grafted on demand)
```

## 1. Tree edges

Parent/child comes from containment (a line contains hemistichs, a hemistich contains words) and from expansion (a letter contains the letters of its name). Siblings are the ordered children of one parent, so recitation order is preserved exactly.

| level | kind | count | branching |
|---|---|---|---|
| 0 | corpus | 1 | — |
| 1 | section | 17 | 17 |
| 2 | line | 109 | ~6 per section |
| 3 | hemistich | 218 | 2 per line |
| 4 | word | 1005 | ~4 per hemistich |

## 2. Graph edges — the constellations

A node's container handle is `C<digital-root>.<ring position>`, both derived from its abjad total. Two nodes anywhere in the corpus that agree on both are in the same container and are one hop apart, whatever their depth or section.

## 4. Traversal

```
tree walk    : parent / children / siblings        -- order-preserving
graph jump   : container(node) -> [equivalents]    -- order-destroying, O(1)
hybrid route : jump, then walk down the new tree   -- context switch
```

The four bootloader opcodes are exactly this instruction set: three tree moves (PARENT, GRANDPARENT, IDENTITY) and one graph move (SHIFT). See doc 03.
