# 05 — Hash address lookup tables

> Generated by the ABJADCOMPUTER engine. Every value below is a sum of

## 1. Address format

```
J<value> / D<depth> / P<path> / S<state>

  J  concatenated abjad total of the node's surface form
  D  expansion depth at which the node sits
  P  positional offset inside the parent  (e.g. 29.ajuz.3)
  S  orthographic state bit  0 = waqf (ة→ه=5), 1 = waṣl (ة→ت=400)
```

Every component is recomputable from the node itself, so the key is a *function of the datum* rather than a label assigned to it. That is what makes retrieval a single dictionary probe instead of a search.

## 2. Cost

| operation | method | cost |
|---|---|---|
| resolve address → node | dict probe on the key | O(1) average |
| fetch a node's container | dict probe on the bucket handle | O(1) average |
| jump to an equivalent node | index into the container list | O(1) |
| enumerate a whole container of k nodes | list read | O(k) |
| execute an address as a function | op-table dispatch + one hop | O(1) |

**On the fully-connected claim.** A container of *k* nodes behaves as a clique — any member reaches any other in one hop — but the edges are never materialised. Only membership is stored, so the structure costs O(n) rather than O(n²) while preserving single-hop reachability. Over this corpus:

| quantity | value |
|---|---|
| nodes | 1350 |
| containers | 243 |
| containers with ≥2 members | 233 |
| largest container | 53 |
| edges implied (clique semantics) | 5781 |
| membership cells actually stored | 1350 |
| storage saving | 4431 cells (77%) |
